## 3. 发布后问题快速响应流程
```
用户反馈 (群/表单/DM)
     ↓  (5 分钟内分级)
┌──────────────┬───────────────┬───────────────┐
│ P0 (崩/挂)    │ P1 (主流程坏)  │ P2/P3 样式/文案 │
│ 立即回滚      │ 2 小时内 hotfix │ 下个版本修复   │
└──────────────┴───────────────┴───────────────┘
     ↓
 P0/P1: 创建紧急 hotfix 分支，测试通过后走金丝雀 1%→100%
```

## 4. 持续优化机制 (每两周 Sprint)
| 时间点 | 动作 | 产出 |
|---|---|---|
| 周一 10:00 | 上周用户体验评估会 + 性能再测 1 次 | UX 周报 + 性能趋势图 |
| 周三 15:00 | 缺陷 triage：排序优先级 + 决定入哪次迭代 | Backlog 列表 |
| 周五 17:00 | Sprint Demo + 发布候选评审 | 是否 release go/no-go |

## 5. 用户反馈归档
- 每周导出表单 Excel 存 `_qa/user-feedback/YYYY-WW.xlsx`
- 高频 Top-5 问题 → 转入 GitHub Issues / 内部缺陷
- 每条用户反馈都有回复（48h 响应 SLA）
